# 最近朗读记录设计

## 目标

在不上传网络的前提下，仅在本机持久化最近三次成功启动的朗读记录。记录同时覆盖选区朗读与用户显式触发的剪贴板朗读，并在“最近朗读”页面和菜单栏显示真实数据。

## 非目标

- 不保存超过三条记录。
- 不上传、同步、分析或记录到诊断日志。
- 不增加“重新朗读”、删除单条、清空历史或历史搜索。
- 不记录未配置语音服务、无权限、文本清洗失败或语音未实际启动的请求。

## 数据与隐私

每条 `RecentReading` 包含完整的清洗后朗读正文、来源应用名称和开始时间。选区朗读保留其来源应用；显式剪贴板朗读的来源为“剪贴板”。内置语音服务测试不写入历史。

用户已明确授权完整正文只保存在本机。数据写入应用支持目录中单独的 JSON 文件；目录与文件权限均限制为仅当前用户可读写。正文不得写入 `UserDefaults`、日志、测试快照、网络请求或错误消息。

## 生命周期与排序

`ReadingCoordinator` 在收到当前会话的 `SpeechEngine.onStarted` 回调后写入记录。这样只有真正进入播放状态的请求才会保存，启动前的失败和被替换的旧会话不会产生记录。

新记录始终位于列表最前面；存储层每次写入后只保留最新三条。重复内容不合并，每次实际开始朗读均视为一条独立记录。启动时读取持久化记录并投影到 `ReadlessAppState`，使管理窗口和菜单栏共享同一份内存状态。

## 架构

新增 Core 的 `RecentReading` 模型及 `RecentReadingStoring` 协议，使 `ReadingCoordinator` 只依赖可注入的存储能力。新增 System 的文件存储实现，沿用现有 `LocalCredentialStore` 的私有目录、原子写入及权限模式，但使用独立文件，避免与凭据混合。

`AppDelegate` 负责构造文件存储、加载既有记录并注入协调器；SwiftUI 和菜单栏只从 `ReadlessAppState.recentReadings` 读取。界面页展示完整正文、来源和格式化时间；菜单栏以单行截断形式显示正文预览，但不改变已保存的完整正文。

## 错误处理

历史写入或读取失败不能阻断朗读。失败只以非敏感的“最近朗读记录暂时无法保存/读取”用户提示呈现，不包含正文、文件路径或底层错误。读取失败时使用空列表；之后的成功写入可恢复历史文件。

## 验证

- Core 单测验证文件存储的往返、按时间倒序与三条上限，以及私有目录和文件权限。
- `ReadingCoordinator` 单测验证选区和显式剪贴板在 `onStarted` 后各新增记录；未启动、失败和内置测试语音不写入。
- AppState 与界面源码测试验证页面与菜单栏读取真实状态，而非硬编码样例。
- 运行完整 SwiftPM 测试、Xcode Debug 构建；在已配置的正常安装 App 中手测两种入口、重启后的三条保留及正文展示。

## 回滚

回滚该功能提交即可停止读取和写入新记录；已有本地历史 JSON 文件不会被删除，保留在用户设备上，直到未来由用户明确要求清除。
