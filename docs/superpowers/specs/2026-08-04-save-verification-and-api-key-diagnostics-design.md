# Readless 保存核验与 API Key 诊断设计

## 背景与已确认事实

用户在豆包 V3 设置页点击“保存”后看到“无法保存语音服务设置”，测试按钮也不可用。

现场检查确认：

- `~/Library/Application Support/Readless/voice-credentials-v1.json` 已存在，JSON 有效，包含 `doubao-v3` 槽位，目录权限为 `0700`、文件权限为 `0600`。
- `voice-service-profiles-v2` 已写入 Readless 偏好文件，内容包含当前 V3 资源 ID 与音色 ID。
- 当时同时存在 Xcode Preview、Xcode 调试运行和签名版等多个 Readless 实例，界面状态与持久化状态发生偏差。
- 使用已保存配置直接请求豆包官方 V3 HTTP 接口，服务端返回 HTTP `401`、协议码 `45000010`、消息 `Invalid X-Api-Key`。

因此需要分别处理两个问题：本地保存成功后的误报，以及远程鉴权失败提示不够具体。

## 目标

1. 本地配置与凭据已经可靠落盘时，设置页必须显示保存成功并启用测试按钮，即使底层写入 API 在最后阶段返回了可恢复错误。
2. 豆包明确返回无效 `X-Api-Key` 时，用户应看到可执行的说明：填写新版控制台 API Key，不要填写旧版 Access Token。
3. 本地保存与远程服务验证保持分离；断网、额度不足或服务端错误不得阻止用户保存本地设置。

## 非目标

- 不在保存动作中自动发起语音请求。
- 不自动迁移或猜测旧版 Access Token。
- 不新增 App ID + Access Token 的 V3 鉴权模式。
- 不读取、记录或显示完整 API Key。

## 方案

### 1. 保存后的持久化回读核验

保存流程保持原顺序：

1. 校验表单。
2. 有新凭据时写入 `LocalCredentialStore`。
3. 写入 `VoiceServiceSettingsStore`。
4. 正常完成时返回成功。

如果写入流程抛出错误，保存协调逻辑不立即返回失败，而是回读两个持久化边界：

- 当前活动配置必须与本次提交的配置完全相等。
- 对应凭据槽位必须存在非空凭据。

两项均满足时，视为 durable success：清除错误、清空输入框、更新绿色“凭据已保存”状态并启用测试按钮。任一项不满足时，仍返回 `.persistenceFailed`。

该核验只判断最终持久化状态，不吞掉真正的数据丢失错误。

### 2. 无效 API Key 的用户提示

豆包 V3 的 HTTP `401`/`403` 继续映射到 `.voiceServiceCredentialInvalid`。其用户文案改为：

> 豆包 API Key 无效。请填写新版控制台“API Key 管理”中的 API Key，不要填写 Access Token。

为了避免该文案错误套用到 OpenAI-compatible，错误展示需要知道当前提供商。最小实现是在豆包 V3 提供方返回一个豆包专用的凭据错误，或在错误模型中携带提供商；优先采用专用错误枚举值，避免扩大所有错误的数据结构。

OpenAI-compatible 的现有凭据错误文案保持通用。

### 3. 多实例边界

本次不禁止 Xcode Preview 或调试实例存在。`RuntimeEnvironment` 继续阻止 Preview 初始化全局快捷键与运行时服务。持久化回读确保即使界面与文件系统短暂不同步，保存结果仍以真实落盘状态为准。

## 数据与隐私

- API Key 仍只保存在本机 Readless 应用数据中。
- 日志、测试和错误提示不得输出 API Key 内容。
- 诊断最多记录错误阶段、错误域/代码、凭据是否存在和长度，不记录凭据值。

## 测试

新增或扩展测试覆盖：

1. 写入方法抛错，但配置与凭据回读均匹配时，保存结果为成功。
2. 只有配置或只有凭据落盘时，保存结果仍为 `.persistenceFailed`。
3. 正常保存路径保持成功。
4. 豆包 V3 的 HTTP `401` 映射到豆包专用无效 API Key 错误及明确文案。
5. OpenAI-compatible 的凭据错误仍使用通用文案。
6. 全量 Swift 测试、产品结构测试和签名 App 构建通过。

## 验收标准

- 用户保存有效的本地表单后，真实落盘即显示“凭据已保存”，测试按钮可用。
- 使用当前无效的 32 位值测试时，界面明确指出 `API Key` 无效且不能用 `Access Token` 代替。
- 更换为豆包新版控制台生成的有效 API Key 后，内置测试句可收到并播放 MP3 音频。
