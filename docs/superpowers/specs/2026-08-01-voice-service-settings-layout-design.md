# 语音服务设置排版设计规格

**日期：** 2026-08-01  
**状态：** 已确认（方案 A）

## 目标

将“语音服务”设置页改为接近 macOS 系统设置的双列表单，使服务商、凭据和配置字段能沿同一纵向基线清晰扫读。现有服务商切换、字段验证、Keychain 保存及试播行为不变。

## 视觉与布局

- 编辑器采用固定约 92 pt 的左侧标签列；右侧控件占据剩余可用宽度，不再限制为 230 pt。
- 每行高度维持原生圆角文本框的默认高度；标签与控件垂直居中，行间距约 8 pt。
- 当前服务商选择器位于第一行。豆包显示 App ID、Access Token、Cluster、音色；OpenAI-compatible 以同一布局显示 Base URL、API Key、模型、音色。
- 提示信息单独置于字段组下方，采用低对比度蓝灰底色和 `info` 图标。文案明确：文本直达用户配置的服务商，凭据只保存在 macOS 钥匙串。
- 错误、已保存状态、试播与保存操作位于提示信息之后；操作区沿右侧控件列对齐，避免干扰字段阅读。
- 设置页标题及副标题保持现状，外层卡片保持现有 14 pt 连续圆角与半透明白色材质，确保与当前播放、最近朗读页面一致。

## 组件边界

`VoiceServiceEditor` 继续拥有本地表单状态、已保存凭据标记和保存错误。新增的布局辅助仅负责统一生成标签列与全宽输入控件，不引入新的业务状态或数据模型。

`VoiceServiceView` 继续负责页面标题、外层卡片和编辑器的容器间距。引导页复用同一个编辑器：在较窄窗口内标签列可缩小，但控件始终获得剩余宽度，且不会溢出。

## 数据与错误处理

字段绑定、`save()`、`loadSavedConfiguration()`、服务商可用性和保存禁用规则全部保持不变。`SecureField` 仍不回显已保存凭据；帮助文字继续说明替换凭据的方式。服务商切换后，字段组依现有条件渲染；不支持的服务商仍只显示“即将支持”说明。

## 验收与测试

- 为布局辅助增加一个源码结构测试，验证编辑器不再包含固定 230 pt 控件宽度，并使用统一的标签列宽度。
- 运行 SwiftPM Core 测试，确认配置验证、保存与读取行为未回归。
- 构建 macOS Debug scheme，确认 SwiftUI 类型检查通过。
- 在运行中的 App 中检查豆包和 OpenAI-compatible 两种状态：长文本、错误提示、已保存状态、试播/保存按钮均在卡片内对齐且可见。

## 非目标

- 不新增或改动语音服务商、凭据存储、网络请求或朗读逻辑。
- 不修改主窗口的侧边栏、其它设置页或引导步骤。
