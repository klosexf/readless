# 通用表格朗读设计

## 目标

当选区或用户显式触发的剪贴板文本包含明确的制表符表格时，自动将它转换为稳定、逐行的通用朗读稿。普通文本保持现有朗读行为。

## 非目标

- 不按表格内容推断“对比、指标、时间线、改写建议”等业务含义。
- 不读取视觉样式、扫描无障碍表格树、读取剪贴板富文本，或新增任何权限。
- 不新增 UI 设置、用户手动模式选择、持久化或日志。
- 不能从输入文本中可靠恢复表格结构时，不尝试猜测。

## 识别与降级规则

识别仅依赖输入字符串中明确的结构：Tab 分隔单元格，换行分隔行。识别为表格必须同时满足：

1. 至少有一行列标题和一行内容。
2. 每行至少有两列。
3. 每行的列数一致。

任一条件不成立时，输入交给既有普通文本清洗器；不会读出“表格”提示。首尾空行可忽略，单元格中的空值保留为可听见的“空白”，避免听者丢失列位置。

## 朗读稿格式

识别成功后，格式化器输出：

```text
这是一个 N 列、M 行的表格。
列标题依次是：列一、列二、……。

第 1 行。列一：内容；列二：内容；……。

……

表格朗读结束。
```

第一行固定视为列标题；M 只计算后续内容行。空的列标题使用“第 N 列”，空的内容单元格使用“空白”。单元格内容沿用当前清洗语义：折叠多余空白并过滤独立 URL；无法保留为正文的单元格按空白处理。

## 架构与数据流

在 `readless/Core/TextSanitizer.swift` 的 `DefaultTextSanitizer` 内先完成表格结构识别：它是唯一已经由选区和显式剪贴板两条路径共同注入的纯 Core 边界。识别成功则清洗各单元格并返回通用朗读稿；识别失败则执行现有段落清洗逻辑。

`ReadingCoordinator`、`AppDelegate`、系统适配器、权限、快捷键和播放状态机都不需要变更。由于格式化后的文本仍作为既有 `sanitize` 返回值，选区指纹、分句、播放进度和语音引擎自然使用同一份朗读稿。

## 测试与验证

在 `Tests/ReadlessCoreTests/TextSanitizerTests.swift` 先新增失败用例，再实现最小代码。覆盖：

- 标准两列以上表格的完整朗读稿；
- 单元格空白、额外空白和独立 URL；
- 列数不一致、无 Tab、只有一行这三类不识别情形；
- 普通多段文本仍保留现有换段行为。

完成后运行 `swift test --filter TextSanitizerTests`、全量 `swift test`，以及完整 macOS App Debug 构建。真实手测使用不含敏感正文的示例表格，分别从选区和显式剪贴板入口确认：识别成功时读出标题、逐行字段和结束提示；普通文本不出现表格提示。

## 风险与回滚

不同应用可能不会把视觉表格暴露为 Tab 加换行文本；这种情况下会安全降级为普通朗读。若出现不理想的自动识别，可回滚 `TextSanitizer.swift` 和对应测试的提交；不影响用户设置、权限或已保存数据。
